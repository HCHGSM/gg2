# قائمة التحقق قبل الإصدار (Release Testing Checklist)

> **لماذا هذه القائمة يدوية:** بيئة العمل المستخدمة لبناء وفحص هذا المشروع لا
> تملك اتصال شبكة ولا نظام Windows ولا واجهة رسومية، لذلك لم يكن ممكناً تنفيذ
> `pytest`، أو تشغيل `main.py`، أو بناء ملف exe فعلياً والتحقق منه تلقائياً.
> تم التحقق من كل شيء بالفحص الساكن (قراءة الكود، فحص الاستيرادات، فحص
> الصياغة) — وهو فحص حقيقي وليس شكلياً، لكنه لا يغني عن التشغيل الفعلي.
> نفّذ هذه القائمة على جهازك قبل اعتماد أي إصدار، وأرسل لي أي فشل لإصلاحه.

## 1. الإعداد
- [ ] `pip install -r requirements.txt` ينجح بدون أخطاء
- [ ] `pytest tests/ -v` — كل الاختبارات تنجح

## 2. تطبيق سطح المكتب
- [ ] `python main.py` يفتح شاشة تسجيل الدخول دون أي استثناء (Exception)
- [ ] تسجيل الدخول بـ `admin` / `admin123` (أو القيمة التي عيّنتها) ينجح
- [ ] تسجيل الدخول بكلمة مرور خاطئة يُظهر رسالة خطأ عامة (لا يكشف إن كان اسم المستخدم موجوداً)
- [ ] الضغط على Enter في حقل كلمة المرور يسجل الدخول (تم إصلاحه في هذا التسليم)
- [ ] لوحة التحكم تعرض الإحصائيات دون تجميد الواجهة
- [ ] نقطة البيع (POS): إتمام عملية بيع كاملة تُنقص المخزون وتُسجل الفاتورة
- [ ] محاولة بيع كمية أكبر من المخزون المتاح تُرفض برسالة واضحة
- [ ] المخزون: إضافة/تعديل منتج يعمل ويظهر التغيير فوراً
- [ ] العملاء: إضافة عميل جديد وربطه بفاتورة بيع آجل يحدّث رصيده
- [ ] التقارير: تصدير Excel وPDF ينتج ملفات صالحة للفتح
- [ ] النسخ الاحتياطي (Backup) والاستعادة (Restore) من شاشة الإعدادات يعملان
- [ ] الطباعة (إن وُجدت طابعة إيصالات حرارية) تُخرج إيصالاً مقروءاً
- [ ] إغلاق التطبيق وإعادة فتحه: البيانات المُدخلة سابقاً ما زالت موجودة
      (يتحقق من أن مسار قاعدة البيانات صحيح وليس مؤقتاً)

## 3. تطبيق الويب
- [ ] `python run_web.py` يبدأ الخادم بدون أخطاء
- [ ] `/` يعيد التوجيه لصفحة الدخول إن لم تكن مسجلاً دخولك
- [ ] تسجيل الدخول عبر المتصفح يعمل، وملف تعريف الارتباط (`session_token`) يظهر بخاصية `HttpOnly`
- [ ] بعد 5 محاولات دخول فاشلة خلال دقائق قليلة، تظهر رسالة "محاولات كثيرة جداً" (حد المعدل الجديد)
- [ ] `/dashboard` و`/pos` يعملان بعد تسجيل الدخول
- [ ] `/api/sales` (POST) ينشئ فاتورة عبر واجهة POS في المتصفح
- [ ] `/logout` يمسح الجلسة فعلياً (محاولة الوصول لـ `/dashboard` بعده تُعيد التوجيه لصفحة الدخول)
- [ ] **ملاحظة معروفة:** مسارات `/products` و`/inventory` و`/customers` و`/suppliers`
      و`/expenses` و`/reports` في تطبيق الويب حالياً مجرد إعادة توجيه لـ
      `/dashboard` (لم تُبنَ كصفحات كاملة بعد) — هذه فجوة وظيفية معروفة، وليست
      خطأ ناتجاً عن هذا التسليم. إن أردت تكافؤاً كاملاً بين تطبيق سطح المكتب
      والويب، أخبرني لأحدد نطاق هذا العمل كخطوة تالية منفصلة.

## 4. البناء والتغليف (على جهاز Windows فقط)
- [ ] `python build.py` ينتج `dist\SmartPOS_ERP.exe` بدون أخطاء
- [ ] تشغيل الملف التنفيذي على جهاز/آلة افتراضية لا تحتوي Python مثبتاً مسبقاً
- [ ] لا نافذة console سوداء تظهر عند التشغيل (وضع windowed)
- [ ] أيقونة التطبيق تظهر بشكل صحيح في شريط المهام وFile Explorer
- [ ] إغلاق الـ exe وإعادة فتحه: البيانات محفوظة (يتحقق من إصلاح مسار `%LOCALAPPDATA%`)
- [ ] بناء المثبّت عبر `iscc installer\SmartPOS_ERP.iss` ينجح
- [ ] تشغيل المثبت: يُنشئ اختصار سطح المكتب وقائمة ابدأ، ويعمل التطبيق بعد التثبيت
- [ ] برنامج "إلغاء التثبيت" من لوحة تحكم ويندوز يعمل ويزيل التطبيق بنظافة

## 5. الأمان
- [ ] لا توجد بيانات اعتماد (كلمات مرور) مكتوبة مباشرة في الكود المصدري (تم نقلها لمتغير بيئة)
- [ ] تغيير كلمة مرور المدير الافتراضية فور أول تسجيل دخول في بيئة الإنتاج

إن فشل أي بند أعلاه، أرسل لي رسالة الخطأ الكاملة وسأقوم بإصلاحها فوراً كجزء
من هذا التسليم.
